# 확신도 표기 (Verbalized Confidence)

## 핵심 원칙
확신도는 내부 토큰 확률(logprob)이 아니라, 답변을 생성하는 같은 과정에서 매기는 **자기 평가**다. 별도 호출로 재검증하지 않는다. 그래서 수치는 기록하고 보정해야 의미가 생긴다.

## 출력 형식 (이 순서로 구성한다)
1. **본문** — 결론을 먼저 쓰고, 결론을 떠받치는 핵심 주장마다 바로 뒤에 `[P(Y)=0.xx, 근거 - 설명]`을 붙인다.
   - 형식은 항상 이 하나로 고정한다: 대괄호, `P(Y)=` + 소수 둘째 자리, 쉼표, 근거 표기, 필요하면 ` - ` 뒤에 짧은 설명.
     - 설명 없음: `[P(Y)=0.90, 추론]`
     - 설명 있음: `[P(Y)=0.90, 추론 - 반올림된 비율이라 범위로 환산]`
   - 확신도는 오직 `P(Y)=0.xx` 형태로만 쓴다. 본문의 `%` 수치는 모두 자료·통계 값이며 확신도로 쓰지 않는다.
   - 근거 표기:

     | 표기 | 답의 출처 |
     |---|---|
     | `확인` | 이번 대화에서 도구로 직접 본 것: 웹 검색, 파일, 실행 결과 |
     | `추론` | 확인한 사실이나 지식을 바탕으로 이어서 판단한 것 |
     | `기억` | 도구 없이 웨이트에 학습된 지식만으로 답한 것 (Claude Code의 메모리 기능과 무관) |
2. **가장 불확실한 부분** — 확신도가 가장 낮은 주장 1~2개와, 무엇을 확인하면 확신도가 오르는지 한 줄.
3. **최종 줄** — `🔵 **확신도: P(Y)=0.xx**`. 맨 앞 색 표시는 값으로 정한다:

   | P(Y) | 표시 |
   |---|---|
   | ≤ 0.50 | 🔴 |
   | 0.51 – 0.70 | 🟡 |
   | > 0.70 | 🔵 |

   터미널 마크다운에는 글자색이 없으므로 색 원 이모지로 표시한다. HTML 출력에서는 같은 구간을 글자색(빨강 `#d93025` / 노랑 `#e0a800` / 옅은 파랑 `#5aa9e6`)으로 칠한다.
   P(Y)는 "내 최종 답변이 맞을 확률"이다. P(N)=1−P(Y)라서 적지 않는다.
   - 예/아니오 질문에 "아니오"로 답했다면 P(Y)는 "아니오"가 맞을 확률이다 (사건의 확률이 아니다).
   - 수치 예측이면 괄호로 기준 범위를 밝힌다: `(실제 값이 490억~530억 달러 범위일 확률)`.

본문 표기(1)와 불확실한 부분(2)이 해당 없는 문장 — 인사, 단순 작업 보고, 사용자 말 되풀이 — 에는 붙이지 않는다. 최종 줄(3)은 모든 답변에 넣는다. 사용자가 끄라고 하면 그 대화에서는 전부 생략한다.

## 보정 기준
| P(Y) | 의미 |
|---|---|
| ≥ 0.95 | 이번 세션에서 직접 검증, 또는 틀릴 여지가 거의 없음 |
| 0.80–0.95 | 신뢰할 근거가 있으나 미검증 |
| 0.60–0.80 | 그럴듯한 추론, 반례 가능 |
| < 0.60 | 추측 — 확인 방법을 반드시 제시 |

- 0.05 단위로 근거 강도를 구분한다 (0.7/0.8/0.9 쏠림 방지).
- `기억` 근거의 상한은 주장 종류로 정한다:
  | 주장 종류 | 상한 |
  |---|---|
  | 오래 변하지 않은 상식 (수도, 언어 기본 문법 등) | 0.99 |
  | 널리 알려진 고정 수치 (산 높이, 물리 상수, 주요 역사 연도 등) | 0.95 |
  | 드물거나 자주 바뀌는 수치·날짜·버전, 최근 1~2년 정보 | 0.80 |
  | 그 밖의 학습 지식 | 0.90 |
- **최종값은 중간값의 곱이나 평균이 아니다.** 지지 근거와 약화 근거를 함께 놓고 결론이 맞을 확률을 다시 판단한다. 대체로 가장 강한 지지 근거보다 낮다.

## 예시
> **짜장면**이 더 인기가 많습니다.
> - 한국 중식 하면 대표 메뉴로 짜장면이 먼저 꼽히고, 주문량도 오래도록 1위를 지켜 왔습니다 [P(Y)=0.80, 기억].
> - 다만 설문에 따라서는 짬뽕이 비슷하거나 앞선 결과도 있습니다 [P(Y)=0.65, 기억].
>
> 가장 불확실한 부분은 최근 통계입니다. 배달앱 주문 데이터나 최신 설문을 찾아보면 확신도를 더 올릴 수 있습니다.
>
> 🟡 **확신도: P(Y)=0.70**

## 기록과 보정 (사용자가 요청할 때)
- 정답 여부가 나중에 밝혀지는 답변은 `calibration-log.csv`(이 스킬 폴더)에 한 줄씩 추가한다. 헤더: `date,claim,p_yes,basis,correct` (`correct`는 1/0, 미정이면 비워 둔다).
- 측정: `python calibration.py calibration-log.csv` → 구간별 정답률, ECE, Brier를 출력한다.
- 기록이 30건 이상 쌓이고 어떤 구간이 체계적으로 과신·과소신하면, 위 보정 기준 표를 그 결과에 맞게 고친다.

## 비용
출력 기준 답변 1개당 약 +20~200 토큰 (긴 답변 +10~20%). 자세한 분석은 같은 폴더의 `README.md` "토큰 비용" 절.

## 흔한 실수
- P(Y)를 사건의 확률로 매김 → 답변이 "아니오"인데 P(Y)=0.30처럼 읽혀 혼동. 항상 "내 답이 맞을 확률"로.
- 웹·문서를 실제로 확인하지 않았는데 `확인`으로 표기.
- 중간 주장마다 다 붙여 본문이 태그로 뒤덮임 → 결론을 떠받치는 핵심 주장에만.
