# confidence — Claude Code 답변에 확신도(P(Y)) 붙이기

Claude Code가 답변의 핵심 주장마다 **중간 확신도**를 붙이고, 답변 끝에 **최종 확신도** `P(Y)`를 표기하게 만드는 스킬입니다. 기록 CSV로 이 확신도가 실제 정답률과 맞는지 측정하는 스크립트(`calibration.py`)도 들어 있습니다.

```
짜장면이 더 인기가 많습니다.

- 한국 중식 하면 대표 메뉴로 짜장면이 먼저 꼽히고, 주문량도 오래도록 1위를 지켜 왔습니다 [P(Y)=0.80, 기억].
- 다만 설문에 따라서는 짬뽕이 비슷하거나 앞선 결과도 있습니다 [P(Y)=0.65, 기억].

가장 불확실한 부분은 최근 통계입니다. 배달앱 주문 데이터나 최신 설문을 찾아보면 확신도를 더 올릴 수 있습니다.

🟡 확신도: P(Y)=0.70
```

> **중요:** 여기서 P(Y)는 모델 내부의 토큰 확률이 아닙니다. 모델이 근거의 강도를 보고 스스로 매기는 **자기 평가(verbalized confidence)** 입니다. 그래서 기록과 보정을 거쳐야 믿을 만한 숫자가 됩니다.

---

## 왜 이 방식인가

LLM은 확률 모델이므로 "Yes"를 출력할 때 내부에 P("Yes")와 P("No")가 존재합니다. 원래 아이디어는 이 값을 그대로 보여주는 것이었습니다. 하지만 Claude에서는 다음 이유로 불가능합니다.

- 모델은 자기 토큰 확률을 관측하지 못합니다. 생성된 토큰만 다음 입력으로 들어갑니다.
- Claude Messages API는 `logprobs`를 제공하지 않습니다 (2026-10 기준).
- 최신 모델은 `temperature`/`top_p` 지정을 거부합니다.

그래서 LLM 불확실성 추정 방법 6가지를 비교한 뒤 아래와 같이 골랐습니다.

| 방법 | 핵심 아이디어 | Claude 적용 | 비용 | 선택 |
|---|---|---|---|---|
| A. P(True) / P(IK) (Kadavath 2022) | "이 답이 맞나?" True/False 토큰 확률 | ❌ logprob 필요 | 낮음 | |
| **B. Verbalized Confidence** (Lin 2022, Tian 2023) | 확신도를 말로 표현하게 지시 | ✅ 즉시 | 거의 0 | **✅ 채택** |
| C. 샘플링 일관성 / Semantic Entropy | N번 생성 후 일치도 측정 | ✅ API | N배 | 향후 |
| D. 보정 후처리 (Temperature/Platt/Isotonic) | 말한 확률 ↔ 실제 정답률 정렬 | ✅ 정답 데이터 필요 | 낮음 | **✅ 부분 채택** (`calibration.py`) |
| E. Conformal Prediction | 정답 포함 확률을 통계적으로 보장 | ✅ 정답 데이터 필요 | 낮음 | |
| F. 내부 상태 Probe | 은닉층에 분류기 학습 | ❌ 가중치 필요 | 높음 | |

**B를 고른 이유**
1. **즉시 적용:** 지시문만으로 동작해서 코드나 API 호출이 추가로 필요 없습니다.
2. **RLHF 모델에서도 쓸 만함:** Tian et al. (2023)은 RLHF로 튜닝된 모델에서 말로 표현한 확신도가 토큰 확률보다 보정이 더 잘 되는 경우가 많다고 보고했습니다.
3. **약점은 규칙으로 보완:** B 방식의 알려진 약점은 과신과 둥근 숫자(0.7/0.8/0.9) 쏠림입니다. 근거 표기, 근거별 상한, 0.05 단위 구분으로 이를 완화하고, D 방식(기록 → 측정 → 보정)으로 사후 검증합니다.

## 동작 방식

확신도는 **별도의 LLM 호출로 답을 다시 검증해서 나오는 값이 아닙니다.** 답변을 생성하는 같은 한 번의 과정에서, 스킬 규칙에 따라 본문과 함께 확신도 텍스트를 씁니다. 그래서 늘어나는 비용은 호출 횟수가 아니라 답변에 붙는 몇십~몇백 토큰입니다.

## 출력 형식

답변은 다음 세 부분으로 이루어집니다.

1. **본문:** 결론을 먼저 쓰고, 결론을 떠받치는 핵심 주장마다 `[P(Y)=0.xx, 근거 - 설명]`을 붙입니다. 설명은 필요할 때만 씁니다.
   - 예: `[P(Y)=0.90, 추론]`, `[P(Y)=0.90, 추론 - 반올림된 비율이라 범위로 환산]`
   - 확신도는 항상 `P(Y)=` 형식으로만 씁니다. 본문의 `%`는 자료 수치이고 확신도가 아닙니다.
2. **가장 불확실한 부분:** 확신도가 가장 낮은 주장과, 무엇을 확인하면 확신도가 오르는지를 한 줄로 적습니다.
3. **최종 줄:** `🔵 확신도: P(Y)=0.xx`. 최종 답변이 맞을 확률입니다. P(N)=1−P(Y)라서 따로 적지 않습니다.

### 근거 표기

| 표기 | 답의 출처 |
|---|---|
| `확인` | 이번 대화에서 도구로 직접 본 것: 웹 검색, 파일, 실행 결과 |
| `추론` | 확인한 사실이나 지식을 바탕으로 이어서 판단한 것 |
| `기억` | 도구 없이 웨이트에 학습된 지식만으로 답한 것 |

### 색 표시

| P(Y) | 표시 |
|---|---|
| ≤ 0.50 | 🔴 |
| 0.51 – 0.70 | 🟡 |
| > 0.70 | 🔵 |

터미널 마크다운에는 글자색이 없어서 이모지로 표시합니다. HTML 출력에서는 같은 구간을 빨강, 노랑, 옅은 파랑 글자로 칠합니다.

### 보정 기준

| P(Y) | 의미 |
|---|---|
| ≥ 0.95 | 직접 검증했거나 틀릴 여지가 거의 없음 |
| 0.80 – 0.95 | 신뢰할 근거가 있으나 미검증 |
| 0.60 – 0.80 | 그럴듯한 추론, 반례 가능 |
| < 0.60 | 추측. 확인 방법을 반드시 제시 |

`기억` 근거의 상한은 주장 종류에 따라 다릅니다. 오래 변하지 않은 상식은 0.99, 널리 알려진 고정 수치(산 높이, 물리 상수, 주요 역사 연도 등)는 0.95, 드물거나 자주 바뀌는 수치·날짜·버전과 최신 정보는 0.80, 그 밖의 지식은 0.90입니다. 최종 확신도는 중간값을 곱하거나 평균내지 않습니다. 지지 근거와 약화 근거를 함께 놓고 결론이 맞을 확률을 다시 판단합니다.

## 설치

1. 이 폴더를 Claude Code 개인 스킬 폴더에 복사합니다.
   ```
   ~/.claude/skills/confidence/
   ```
2. 모든 답변에 항상 적용하려면 `~/.claude/CLAUDE.md`에 다음을 추가합니다. 스킬만 설치하면 관련 질문에서만 로드됩니다.
   ```markdown
   # 확신도 표기

   모든 답변에 확신도를 붙인다. 세부 규칙(형식, 보정 기준, 기록·보정)은 `confidence` 스킬에 있으며, 세션의 첫 답변 전에 이 스킬을 로드한다.

   스킬을 로드하지 못한 경우의 최소 규칙:
   - 핵심 주장 뒤에 `[P(Y)=0.xx, 확인|추론|기억]`.
   - 답변 맨 끝에 `🔵 **확신도: P(Y)=0.xx**` — 내 최종 답변이 맞을 확률. P(N)=1−P(Y)라서 생략. 색 표시: ≤0.50 🔴, 0.51–0.70 🟡, >0.70 🔵.
   ```
3. 새 세션을 시작해 아무 질문이나 해 봅니다. 답변 끝에 확신도 줄이 붙으면 설치가 끝난 것입니다.

끄려면 대화 중에 "확신도 표기 꺼줘"라고 하거나, `CLAUDE.md`에서 위 블록을 지우면 됩니다.

## 확신도 검증 (보정)

정답 여부가 나중에 밝혀지는 답변을 `calibration-log.csv`에 기록합니다.

```csv
date,claim,p_yes,basis,correct
2026-10-30,"Claude Messages API에 logprobs 필드 없음",0.95,확인,1
2026-10-30,"화성시 10/30 오후 비 안 옴",0.70,확인,
```

`correct`는 맞으면 1, 틀리면 0을 적고, 아직 모르면 비워 둡니다. 측정은 다음 명령으로 합니다.

```bash
python calibration.py calibration-log.csv
```

```
채점된 기록: 20건

구간              건수     평균 P(Y)      실제 정답률      차이
0.60-0.70       10        0.65        0.50   -0.15
0.90-0.95       10        0.90        0.70   -0.20

ECE   = 0.175  (0에 가까울수록 보정이 잘 됨)
Brier = 0.261  (낮을수록 좋음)
```

- **ECE** = Σ (구간 건수 / 전체) × |실제 정답률 − 평균 확신도|
- **Brier** = 평균 (P(Y) − 정답)²

기록이 30건 이상 쌓였는데 특정 구간이 꾸준히 과신하거나 과소신하면, `SKILL.md`의 보정 기준표를 그 결과에 맞게 고칩니다. Python 3.7 이상이 필요하고 표준 라이브러리만 씁니다.

## 토큰 비용

| 항목 | 규모 (추정) |
|---|---|
| 입력: 규칙 텍스트 | 요청당 수백~1,000 토큰. 대부분 프롬프트 캐시로 처리 |
| 출력: 중간 태그 | 태그당 약 10~15 토큰 |
| 출력: 불확실한 부분 + 최종 줄 | 약 40~110 토큰 |

답변 1개당 출력이 약 **+20~200 토큰** 늘어납니다. 긴 답변에서는 +10~20%, 짧은 답변에서는 +20~60%입니다. Opus 5.5 API 정가로 환산하면 답변 1,000개당 약 $3입니다. 이 수치는 글자 수로 낸 추정치이고 실측은 아닙니다.

## 한계

- 표기된 값은 내부 확률이 아니라 자기 평가입니다. 보정 전까지는 가설로 다뤄야 합니다.
- 모델이 틀린 사실을 확신하는 경우(자신 있는 환각)는 이 방식으로 잘 잡히지 않습니다. 이런 경우에는 샘플링 일관성(C)이 더 효과적입니다.
- 지시문을 따르는 데 의존하므로 긴 대화에서는 가끔 표기가 빠질 수 있습니다.
